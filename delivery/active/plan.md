# Plan: шов агента переписки, часть «А2» — черновик по брифу этапа — кому положен, что видит этап, где лежит

## Approach

- `draft_answer(session, writer, reply_id, *, again, force)`: цель ответа (`_target`), этап из реестра, настройки
  (`_refusal` — не человек, переписка закрыта, этапа нет в реестре, не настроен, выключен), `_done` — отвечен,
  решён, уже написан. Переписка (`_turns`), `Conversation`, бриф этапа; пропуск → `_skipped`, иначе `_written`
  (потолок расхода, писатель с промптом и моделью этапа, расход операцией этапа). Запись `_store` — вставка с
  заменой по `uq_agent_drafts_reply`, решение обнуляется. `DraftOutcome.notice` — что увидит крючок.
- `announce(outcome)` — крючок `on_draft` этапа после коммита, только `drafted`/`escalated`, сбой — в лог.
- `Brief.sign_as` — `_written` отдаёт писателю имя брифа (`Request.sign_as`, ключ `sign_as` запроса модели), если оно задано, иначе `OUTREACH_SENDER_NAME.strip()`, как до шва; петля правки судьи (Б) копирует запрос через `replace` — имя переживает правки.

## Rejected alternatives

- Пропуск брифа без строки (как «невидимый `no_reply_needed`» CRM) — отклонено, потому что пропуск обязан быть виден.
- Крючок внутри записи — отклонено, потому что уведомление ушло бы о незакоммиченном черновике.

## Risks

- `drafting.py` — 393 строки (предел 500): петля судьи — в отдельном модуле (Б).
- Бриф соседнего модуля зовётся с сессией: его запросы — в транзакции черновика.
