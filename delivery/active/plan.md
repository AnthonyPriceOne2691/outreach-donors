# Plan: срез 1.5, часть 1.5b — раздел «Продажи» на экране

## Approach

- **Экран** — `frontend/src/sales/`: `SalesPage.tsx` (адрес, запросы, сводка, вкладки
  `SalesTabs`), `LeadsPane.tsx` (вкладка лидов: `useLeads`, `pageBack`), `LeadsTable.tsx`
  (фильтры под колонками), `HypothesesTable.tsx`, `FixedTable.tsx` (каркас таблиц),
  `Pending.tsx` (ворота «раздел не прочитан»), `leadFilters.ts` (адрес ↔ фильтры),
  `ImportWizard.tsx` (`useImportWizard`, `WizardSteps`), `ImportColumns.tsx`,
  `ImportReport.tsx`, `importMapping.ts` (чистые правила).
- **Клиент и слова** — `api/sales.ts`, `api/salesTypes.ts`, `api/salesLabels.ts`; сверка кодов
  сервера с типами и подписями — отдельным PR после этой части (решение владельца 04.10).
- **Права** — пункт меню и маршруты под `RequireAccess permission="sales"`; снимок прав в
  `fixtures.ts`, таблица ролей в `docs/WEB_LAYER.md`.
- **Замеры** — каталог `scripts/ui_screens_sales.py`, `ui_contrast.py`, `ui_hover.py`.

## Rejected alternatives

- Типы и подписи в общих `types.ts`/`labels.ts` — отклонено, потому что те стоят в тающем
  baseline длины (988 строк при пределе 500), и гейт длины новый раздел туда не пускает.
- Форма загрузки через общий `request` — отклонено, потому что он умеет только JSON, а
  `client.ts` вне точек среза; общий помощник формы — отдельным общим PR.
- Свой перечень причин на экране — отклонено, потому что коды пишет очистка (1.4): список
  фильтра берётся из ответа сервера.
- Снимать пары дублей переименованиями — отклонено, потому что jscpd сравнивает токены
  буквально: переименование убрало бы пару из счёта, не убрав копию; пары сняты структурой.
- Пересъёмка снимков и контраста после дедупликации — отклонено, потому что CSS не тронут, а
  разметка во всех 30 состояниях совпала побайтно (сверка DOM).
- Четыре PR по задачам — отклонено владельцем, потому что промежуточные головы красные по
  гейтам дублей и сложности и требовали бы роста снимков.

## Risks

- Гонка ответов предпросмотра (два быстрых переключения) прикрыта номером запроса, тестом
  не покрыта: заглушка `serve()` отвечает мгновенно и по порядку.
- Отчёт на тысячи строк — первые 300 и «Показать все»; 5 000 строк разметки не мерились.
- Живой прогон — на синтетическом файле и своей базе; на настоящей базе — заложено.

## Rollout / migration

Без миграции. Часть 2 из 2, одним PR под вейвер строк владельца (решение 04.10).

## Test / eval strategy

vitest через `serve()` (незаписанный запрос роняет тест, ожидания с `SCREEN_WAIT`); замеры A3 — живьём (verify-report); дедупликация —
сверка DOM и порядка запросов до/после; обратные прогоны мастера и страховок.
