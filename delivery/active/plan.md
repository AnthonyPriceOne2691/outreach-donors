# Plan: срез 4.6a `sales-chain` — цепочка писем продаж в базе и экран правки (часть 1)

## Approach

- **Данные** — `backend/features/sales/models.py`: `SalesChainTemplateModel` (`sales_chain_templates`;
  ключ `uq_sales_chain_templates_key` «набор, шаг, язык» с `NULLS NOT DISTINCT`; проверки
  `ck_sales_chain_templates_step` — шаг 1–3 и `ck_sales_chain_templates_subject` — тема только у шага 1;
  гипотеза — `ForeignKey(..., ondelete="RESTRICT")`). Миграция `723e3ddab31f` (после головы main
  `a51e5688f79e`), значение журнала — отдельной ревизией `cbc5aadf4fc2` (`ADD VALUE IF NOT EXISTS`).
- **Текст шаблона** — `backend/features/sales/chain_text.py`: разбор зон (`zones_of`), правила записи
  (`step_template`: шаг, язык, тема, тело, зоны, подстановки, метрики, коридор), подпись и адрес из
  настроек (`unsigned`), предпросмотр с выдуманными значениями (`preview`). Без базы.
- **Набор, версия, запись** — `backend/features/sales/chain.py`: `resolve` (своя цепочка гипотезы
  целиком или общая целиком), `version_of`/`set_version`, `Chain.missing`/`check_ready` для 4.6b,
  `save` (upsert по ключу, журнал в транзакции вызывающего, без изменений — без журнала).
- **Файл вне репозитория** — общий для двух загрузок `backend/features/sales/outside.py` (`read_json`,
  `repository_of`, сверка `sort_against`); `kb_load.py` (3.1) переведён на него.
  `backend/features/sales/chain_load.py` — `read` → `plan` → `apply`, журнал одной записью.
- **API** — `backend/api/sales/chain.py` + `chain_schemas.py`, роутер входит в роутер раздела
  (`routes.py`); отказы — существующие строки `api/errors.py` (`TemplateError` 400, метрики 400,
  `UnknownHypothesisError` 404).
- **Консоль** — `outreach sales-chain-load` в `backend/cli/sales.py` / `main.py` (подсказка второго Ctrl-C).
- **Экран** — `frontend/src/sales/`: `ChainPane.tsx` (набор, карточки языков, шаги), `ChainStepModal.tsx`

  вкладка — `leadFilters.ts`, `SalesPage.tsx`.

  `sales-chain-step`), `ui_contrast.py`, `ui_hover.py --path /sales?tab=chain`.

## Rejected alternatives

- Шаблоны продаж файлами рядом с кодом, как у доноров — отклонено, потому что репозиторий публичный:
  тексты продаж — коммерческие и живут только строками базы.
- Текст «по умолчанию» для пустой цепочки — отклонено, потому что умолчание в коде — коммерческий текст
  в публичном репозитории и письмо, которого никто не писал; пустая цепочка — отказ словами
  (`check_ready`), экран — «цепочка не задана».
- Добирать недостающие шаги гипотезы из общего набора — отклонено, потому что добивка общего набора к
  своему первому письму гипотезы напоминала бы не о том письме; набор берётся целиком (`resolve`).
- Разбор шаблона доноров `template.parse` — отклонено, потому что он требует набор зон доноров и подпись
  в шаблоне, а у продаж подпись и адрес допишет сборка из «Отправителя»; свой разбор `zones_of` в том же
  формате зон.
- Зоны `rewrite` в добивках — отклонено, потому что у доноров модель в добивках не участвует
  (`okf/followup-chain.md`: напоминание — три строки, уникальность даёт первое письмо).
- Версия цепочки счётчиком правок или временем — отклонено, потому что откат правки обязан вернуть
  прежнюю версию, а сборка и калибровка — узнавать текст по строке версии (как версия базы знаний 3.1).
- Одна версия на весь набор (оба языка) — отклонено, потому что письмо пишется на одном языке: правка
  английского шаблона не должна менять версию русских писем.
- Отдельная таблица наборов — отклонено, потому что набор — это гипотеза или общий: `hypothesis_id` с
  `NULLS NOT DISTINCT` держит ключ без лишней сущности.
- Удаление шаблонов — отклонено, потому что выключенный шаблон сохраняет текст и след в журнале, а
  выключенные свои шаги гипотезы — заготовка, при которой гипотеза остаётся на общей цепочке.
- `PUT` для записи шага — отклонено, потому что клиент экрана шлёт JSON методами GET/POST/PATCH, а правка
  общего `frontend/src/api/client.ts` вне точек среза; запись — `POST` по ключу «набор, шаг, язык».
- Своя ошибка цепочки в `api/errors.py` — отклонено, потому что `ChainError` — наследник `TemplateError`
  доноров, и его 400 словами уже сопоставлен; общий файл не тронут.
- CSV для загрузки — отклонено, потому что тело — зоны и абзацы, в CSV их держали бы в кавычках со
  сдвоенными кавычками.
- Загрузка частями и перезапись отличающихся без `--update` — отклонено, потому что цепочка по половине
  шагов — это письма, которые не соберутся, а старый файл молча откатил бы правку с экрана.
- Вторая копия чтения файла и сверки рядом с `kb_load.py` — отклонено, потому что jscpd считал клон, а
  правило «вне репозитория» разошлось бы на первой правке одной из копий; общий `outside.py`.
- Мерить текст поля окна шага шаблоном стенда — отклонено, потому что вырезка берёт кромку поля из
  чернил и даёт 4,39 при 5,86 по строке букв; меряется плотным выдуманным телом (`STEP_BODY`).
- Непрозрачная шапка у своего окна шага — отклонено, потому что прозрачная шапка окна при прокрутке —
  общий `frontend/src/theme.ts`, и чинить её только у продаж запрещено (правило «один раз»); находка.

## Risks

- **Первый включённый свой шаг гипотезы переключает её язык на свою цепочку целиком** — пока в ней нет
  трёх шагов, письма гипотезы на этом языке не собираются (экран говорит «цепочка неполна»). Заготовка —
  выключенными шагами; включать — когда заданы все три.
- Подпись и адрес из настроек сверяются при записи шаблона: шаблон, записанный до того, как задали
  подпись, её текст может содержать. Сборка 4.6b должна сверить ещё раз (`unsigned` на готовом письме).
- Формат версии `chain-` + 12 знаков закреплён тестом; смена канона отпечатка (поля, порядок) меняет
  версии всех писем — только вместе со сборкой и калибровкой.
- Две одновременные записи одного шага: ключ держит база, второй запрос — 500, а не 409 словами (как у
  базы знаний 3.1) — открытый вопрос.
- Таблица ссылается на гипотезу (`hypothesis_id`): цикл миграции 1.1a в тесте откатывает сначала её миграцию
  (`DEPENDENTS` в `tests/test_sales_model.py`); следующая ссылка на таблицы 1.1a — ещё строка там.
- Нумерация: у шаблонов шаги 1–3, у `messages.step` доноров 0–2 — 4.6b переводит в одном месте.
- Main ушёл вперёд на #174 (`448ef4c`, без миграций): пробное слияние без конфликтов; голова миграций
  одна — `cbc5aadf4fc2`.
- Живой прогон — на выдуманных текстах; настоящие тексты — «заложено» (файлом через консоль).

## Rollout / migration

Две миграции (`723e3ddab31f` → `cbc5aadf4fc2`), только создают: на живой базе данные не трогаются.
Откат снимает таблицу (своего типа у неё нет; цикл под тестом и живьём). Значение журнала
`sales_chain_changed` откатом не снимается — `ADD VALUE` необратим, повтор не ломается (`IF NOT EXISTS`,
тест повтора).

## Test / eval strategy

Тесты на настоящей базе дерева (правила, набор, версия, журнал, ключ и проверки базы, цикл миграции),
API через `httpx` (403 на каждом маршруте, таблица маршрутов сверена), консоль через `build_parser` и
`main`; vitest через `serve()` (незаписанный запрос роняет тест); сверка кодов сервера с экраном
(`tests/test_sales_chain_screen.py`). Красный прогон на main без кода среза; мутанты — тема «Re:»,
метрики в теле, незнакомая подстановка, версия без темы или тела, смешение наборов, выключенный шаг в
цепочке, подпись из настроек, «не задана» на экране, тема добивки. Замеры экрана — живьём (verify-report).
