# Plan: срез 1.1b `sales-stage`, часть «в» — экран и сводка знают этап продаж

Перенос на main `05d75d9` (06.10): сервер части — как в срезе на старом main, кроме журнала сборки;
фронт переложен — этап строки отдельным типом в файле модуля, экраны почты не тронуты. Перенос на main
`f9819da` (07.10): код части — без правки (меняется только контекст — `threadState` части «б» в импорте);
добавлен тест донора после #193. На main `f9819da` — конфликт импорта в `types.ts` с #194 (`Offer`): склейка.

## Approach

- **Журнал сборки** — `backend/api/letters/routes.py`: в словарь `_STAGE_TITLES` добавлена запись
  продаж; полноту по `Stage` сверяет тест (`test_audit_names_every_stage_in_words`). Сборку продаж
  маршрут отказывает раньше (часть «а»).
- **Отбор прогона** — `backend/features/runs/exclusions.py`: `match stage` с донорской частью в
  `_donor_answers`, `ADVERTISERS | SALES` — явной веткой без них.
- **Этап строки на фронте** — `frontend/src/api/stages.ts` (новый): `Stage` — все этапы сервера,
  `THREAD_STAGE_NOTES` — пометка этапа в шапке. В `types.ts` — `ThreadCard.stage` и `StopEntry.stage`
  становятся `Stage`, `ThreadState` получает `sales_pending`; `LetterStage` остаётся этапами, которые
  ведёт почта (`core.stages.MailStage`). В `labels.ts` — подпись `sales_pending`.
- **Переписка** — `frontend/src/threads/ThreadPage.tsx`: пометка этапа в шапке из словаря; у ответа
  продаж (`card.stage === 'sales'`) нет формы цены, «взять лид» и поля ответа, есть строка
  «Ждёт человека: <причина сервера>.». У донора — как без части: ответ и его пояснение у поля (#193) —
  тест `у донора пометки этапа нет, а пояснение у поля ответа на месте`.
- **Сверка с сервером** — `tests/test_sales_stage_screens.py` читает `stages.ts`, `types.ts` и `labels.ts`
  как текст: `Stage` = `Stage`, `LetterStage` = `MailStage`, `ThreadState` = `ThreadState`, подписи —
  все значения.

## Rejected alternatives

- `LetterStage` с `sales` и записи `sales` во всех словарях экранов почты (как в срезе на старом main) —
  отклонено при переносе, потому что `types.ts` у потолка длины (1009 при снимке 988 + 30), записи о продажах в
  `LettersPage.tsx`, `LetterDraftEditor.tsx` и новом `AgentPage.tsx` (#176) — текст экранов, которых нет;
  `LettersPage.tsx` и `test/fixtures.ts` — пути соседней сессии этой ночью.
- Функция `_stage_title` с `match` вместо словаря (как в срезе на старом main) — отклонено при переносе,
  потому что соседняя сессия добавляет в `api/letters/routes.py` маршрут отправки очередью, и прежнее имя словаря
  ей может понадобиться; полноту держит тест по `Stage`, а не mypy.
- Показать продажи переключателем этапов — отклонено, потому что очередь и отправка продажам отказывают.
- Сверка типов генерацией клиента из OpenAPI — отклонено, потому что генератора в проекте нет (новая зависимость —
  решение владельца).
- Пометка этапа в шапке у доноров — отклонено, потому что доноры — основной поток.

## Risks

- `api/letters/routes.py`, `threads/ThreadPage.tsx` — файлы соседней сессии этой ночью (маршрут
  отправки очередью; карточка внизу диалога): правки части — одна строка словаря и места выше карточки;
  таблица пересечений — в отчёте среза.
- Экран переписки и список диалогов брали подпись состояния без запасного значения — с частью «б»
  читают через `threadState` (просьба соседней сессии).

## Rollout / migration

Миграций нет. Сервер и фронт выкатываются одним образом из одного коммита.

## Test / eval strategy

pytest `tests/test_sales_stage_screens.py` (сверка значений и подписей, журнал для каждого этапа,
главная на базе, диалоги через API, отбор прогона на базе для трёх этапов); vitest
`frontend/src/threads/ThreadPageSales.test.tsx` через `serve()` (продажи и донор). Мутанты — повторно в
переписанных местах (журнал, `Stage` и `LetterStage` фронта, пометка этапа) и для теста донора (условие
ответа, донор как продажи, пометка у донора).
