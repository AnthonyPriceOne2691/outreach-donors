# Plan: шов агента переписки, часть «А1» — реестр этапов и таблица черновиков

## Approach

- `backend/features/agent/stages.py` — типы шва и реестр. Части этапа с умолчанием «как у первых двух этапов»:
  промпт `agent/prompts/answer.md`, версия `agent-answer-v1`, модель `LLM_AGENT_MODEL`, операция `agent_draft`,
  бриф `no_brief`, судьи нет, автопилот выключен. `agent_stage(stage)` — отказ `UnknownAgentStageError` (404).
- `writer.Request` — `facts`, `prompt`, `model`; `user_message` кладёт `facts` только при фактах; `build_payload`
  берёт промпт этапа (`load_prompt(path)`, кэш на путь), `AgentWriter.write` — модель этапа или клиента.
- Таблица и модель — из заготовки `cc68357`, поля — по интерфейсу; миграция — новая таблица и новый тип, после
  головы `fc721be3d031`.

## Rejected alternatives

- Кортеж этапов + словари частей по этапу — отклонено, потому что части разъехались бы по пяти словарям, новый этап —
  `KeyError` после оплаченного вызова модели.
- Флаг `needs_human` рядом со статусом (как в заготовке) — отклонено, потому что это два источника правды о «ждёт человека».
- Журнал «только добавление» вместо одной строки на ответ — отклонено, потому что интерфейс задаёт одну строку
  со статусом; попытки — в `meta`.

## Risks

- Ревизия `7ccbaf6d840a` и «цены списком» соседней сессии (#194, `ad4a79bc6000`) — обе после `fc721be3d031`;
  #194 и #180 влиты 07.10 во время переноса шва — у `7ccbaf6d840a` перецепка `down_revision` на голову main
  (сейчас `cbc5aadf4fc2`), иначе две головы.
- Типы шва — контракт для 3.2a: имена после слива меняются только вместе с адаптером продаж.

## Rollout / migration

Голова миграций — 7ccbaf6d840a (одна голова; после fc721be3d031). Только добавление; откат — в `downgrade` ревизий. Слив — после окна соседней сессии, по
решению владельца. Main ушёл дальше базы шва: #194 (`ad4a79bc6000`) и #180 (`723e3ddab31f` → `cbc5aadf4fc2`) —
`down_revision` ревизии `7ccbaf6d840a` перецепляется на голову main на момент PR (на `58b9806` — `cbc5aadf4fc2`).

## Test / eval strategy

`tests/test_agent_stages.py` — на настоящей базе дерева (`outreach_test_<хэш дерева>`); модель — подставной HTTP
(`httpx.MockTransport`) или писатель-подмена; почта — `NullTransport`/`Recording`. Красный прогон — тесты части на
голове предыдущей части; мутанты — по обязательным пунктам шва (`scratchpad/mutants.py`, таблица в agent-report).
