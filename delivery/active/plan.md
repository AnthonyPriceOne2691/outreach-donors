# Plan: срез 1.4, часть 1.4a — страна и часовой пояс

## Approach

- **Таблица стран — данными** (`geo.py`): 249 кодов ISO-2, названия RU и EN, псевдонимы
  («USA», «UK», «Deutschland»). Сопоставление — по нормализованному названию, без угадывания
  по подстроке: «Нигер» не должен совпадать с «Нигерией».
- **Пояс:** колонка файла побеждает страну (у США четыре пояса — колонка точнее); иначе
  пояс страны — у стран с одним поясом; у стран с несколькими — `CAPITAL_ZONES` (столичный)
  с замечанием в отчёте строки — решение владельца 04.10, лучше приблизительный пояс,
  чем пустой: отправка в рабочие часы всё равно попадёт в день. Без столицы — пусто.
- **Непонятое поле не стоит строки** (урок L67): лид загружается, замечание — в отчёте.
- Колонки `country` и `timezone` у лида есть с 1.1a — миграции нет.

## Rejected alternatives

- Внешняя библиотека стран и поясов — отклонено, потому что это новая зависимость ради
  таблицы на 249 строк, а таблица данными проверяется тестом по форме против базы поясов
  Python.
- Угадывать пояс по городу или по домену почты — отклонено, потому что это догадка молча,
  без следа в отчёте; поле разрешено не знать.
- Ошибка строки при непонятной стране — отклонено, потому что лид терялся бы из-за поля,
  которое не обязательно (урок L67).
- Пустой пояс у стран с несколькими поясами — отклонено решением владельца 04.10, потому
  что приблизительный пояс со столицы лучше пустого для отправки в рабочие часы.

## Risks

- Столичный пояс для больших стран (США, Россия, Канада) расходится с реальным до 3–4 часов —
  замечание в отчёте называет это; колонка файла снимает риск.
- Страны с несколькими поясами и без столицы (Антарктида, необитаемые территории) — пусто.

## Rollout / migration

Одним PR, без миграции. Часть 1.4b+c — следующим PR под вейвер владельца.

## Test / eval strategy

`tests/test_sales_geo.py` на настоящей базе: форма таблицы (249 кодов, каждый пояс в базе
поясов, `CAPITAL_ZONES` ровно у стран без единого пояса и со столицей), RU/EN/псевдонимы,
столичный пояс с замечанием, колонка побеждает, непонятое не роняет строку, запись в базу;
ожидания 1.3 обновлены. Новые тесты на старом коде — красные (verify-report).
