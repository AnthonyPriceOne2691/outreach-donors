# Plan: модуль «Продажи», Ф2 одним PR — части 2.1, 2.2, 2.3a, 2.3b

## Approach

- **2.1 — своя очередь.**
  - Правило `replies/outcome.to_sales_queue(kind, stage)` — ответ человека в треде продаж; его зовут приём
    (`Inbox._settle` → `Accepted.sales_pending`) и повтор вебхука (`Inbox._repeated` → `Accepted.sales_again`: снимка
    разбора нет, человек не решал). Почта модуля продаж не знает (`mail-does-not-know-sales`): задача ставится строкой
    пути (`queue.SALES_REPLY_JOB`).
  - Постановка — `api/inbound/routes.py`: `_queue_parse` и `_queue_sales` зовут один `_queue` (одна задача на ответ,
    `unique`, повторы `with_retries()`, `RedisError` → 503 с причиной).
  - Очередь — `shared/queue.py` (только добавления); воркер — `workers/main.py --queue {runs,sales}` с планировщиком;
    `health sales`; сервис compose `worker-sales` по образцу `crawler`; `WRITERS` у `restore.sh`.
  - Исход задачи — `ops/job_outcome._next_try` читает реестр отложенных очереди самой задачи (`job.origin`).
- **2.2 — вид ответа моделью.**
  - `features/sales/reply_kind.KindClient` на общем `shared/llm.post_chat` (возвращает `Refusal`, не бросает); вход —
    `user_message` (тема и письмо между метками, свои метки собеседника погашены, `written_by_hand(text[:20000])`,
    маскирование одним словарём меток, утёкший адрес — отказ до запроса); `build_payload` — пороги вывода по семейству
    модели словарём.
  - `parse_form` читает только `kind`, `confidence`, `quote`, `contact`; `temper` — цитата и адрес из меток, ищутся в
    написанном человеком, не нашлись — уверенность 0.
  - Путь — `sales/replies.decide(found, threshold)`: таблица `ROUTES`, ниже порога или `parse_failed` — ручная
    очередь; `_follow`: `handoff` → точка `mark_for_handoff` (журнал с ключом `thread_id`), `closed` → диалог `CLOSED`.
  - Снимок — `replies.model_parse` с `stage = sales` (вид, уверенность, цитата, адрес, путь, «ждёт ли», причина,
    версия промпта, модель); почта читает только `waits`/`reason` (`outcome.sales_review`); калибровка цены снимки
    продаж пропускает. Отказ модели — записка с пустым `kind`, повтор разбирает заново.
  - Задача — `workers/sales_jobs.handle`: временный отказ — записка закоммичена, `ModelUnavailableError` (очередь
    повторит); постоянный — итог; `LlmCapExceededError` — на начало следующих суток UTC. Потолок — общий
    (`usage.ensure_llm_within_cap`), свой — только у черновиков агента.
  - В3а — `scripts/eval_sales_reply.py`: синтетика, `--golden` по манифесту, `--drop-kind`; ворота: полнота
    `wants_to_talk` ≥ 95 %, `unsubscribe` 100 %, опасных 0, ложных отписок 0.
- **2.3a — другой контакт.** `SalesReplies._refer` → `referral.refer`: лид исходного диалога — по адресу контакта
  диалога на его домене (`origin_lead`); новый `SalesLeadModel` той же гипотезы и домена, `source=referral`,
  `referred_from_thread_id`; исходный диалог `CLOSED` до очистки; `cleaning.clean_leads` без коммита. «Другое
  направление» очистки — только диалоги доноров и рекламодателей. `ConfigError` проверяльщика ловится в `_refer`.
- **2.3b — автоответ и отписка.** `SalesReplies.handle` ветвится по виду правил: автоответ → `ooo.postpone` (дата
  возвращения правилами, окно 120 дней, сдвиг только вперёд), отписка → `unsubscribe.close_address` (`suppress` без
  этапа, `stop_pending(email)`, `stop_chain`, диалог `UNSUBSCRIBED`); состояние «отписался» — из снимка
  (`sales_closed_address`). `ReplyRepository.suppress` — пропуск только при `stage IS NULL AND expires_at IS NULL`.

## Rejected alternatives

- Один воркер на две очереди или приоритет в `runs` — отклонено, потому что идущая часовая задача держит процесс
  целиком: ответ лида ждал бы конца прогона.
- Импорт модуля продаж из `replies` — отклонено, потому что его запрещает контракт `mail-does-not-know-sales`; путь
  задачи строкой — как у разбора цены.
- Своя таблица вида ответа — отклонено, потому что «ждёт ли ответ человека» читают диалоги (почта), а почта не
  импортирует продажи; снимок у ответа читается без импорта.
- Вид отказа модели `parse_failed` — отклонено, потому что отказ закэшировался бы видом и повтор его бы не тронул.
- Модель решает «нужен ли ответ» и путь — отклонено, потому что путь решает код: лишние поля её ответа не читаются.
- Пере-снять снимок дублей jscpd под сборку запроса — отклонено, потому что у main снимок без запаса, рост — только
  строкой `baseline_growth_waiver:` с решением человека, а копия убирается кодом.
- Отказ задачи до вызова модели при неверной настройке проверки адресов — отклонено, потому что вид до вызова
  неизвестен: остановился бы разбор всех ответов продаж, а после трёх повторов ответ застрял бы без снимка.
- Дата возвращения моделью — отклонено, потому что автоответ решают правила приёма без модели; дата правилами
  «дословно в тексте» по построению.
- Своя запись стоп-листа в модуле продаж — отклонено, потому что правило одно (`ReplyRepository.suppress`): его изъян
  чинится там, где он живёт.

## Risks

- Новый сервис — изменение выкатки: скрипт соседней сессии ждёт 11 healthy и сверяет образы по списку; станет 12 и
  `worker-sales` (правит та сессия на выкатке, по слову владельца).
- Пределы длины: `replies/pipeline.py` 498/500, `replies/repository.py` 495/500, `sales/cleaning.py` 493/500.
- Пин `gpt-5` и порог 0,8 — по живому прогону на синтетике (28 из 28); пересмотр — на наборе владельца.
- Правка `suppress` меняет и доноров — только в двух краях, в сторону docstring; у адреса может стать две строки.
- Отписка словами по виду модели — необратимое без человека (стоп-лист снимают руками, снятые сроки не
  возвращаются): вход только не ниже порога, ворота eval держат «ложных отписок 0».

## Rollout / migration

Голова миграций — `739817077a57` после `75242c2ed7ba` (одна голова); `ADD COLUMN` (nullable) + FK `SET NULL` + индекс
на малой таблице лидов, откат — `drop_index` + `drop_column`. Перед сливом — перецепка на голову main того дня.
`worker-sales` выкатывается по слову владельца; до выкатки задачи продаж копятся в очереди `sales` (писем продаж нет,
пока почта им отказывает, — ответов продаж тоже). Новые настройки не обязательны: `SALES_REPLY_CONFIDENCE` 0,80,
`SALES_OOO_DELAY_DAYS` 7, `LLM_SALES_CLASSIFY_MODEL` gpt-5, `SALES_GOLDEN_DIR` пуст.
