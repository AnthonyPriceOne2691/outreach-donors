# Plan: модуль «Продажи», срез 1.3 — загрузка базы лидов

## Approach

**Чтение — общий `contacts.sweep_input.read_records`, второго читателя CSV нет.**
Правило «один раз» (договорённость с сессией outreach-donors, 01.10): кодировку, BOM, разделитель и номера
строк файла судит одна функция для всех направлений. `read_records` берёт путь,
поэтому байты с экрана и из Google пишутся во временный каталог под исходным
именем: его называют отказы («файл база.csv не в UTF-8»). Общий файл не меняется.

**Заголовок и сопоставление — логика продаж** (`sales/columns.py`):
- поле → синонимы — таблицей данных: новый заголовок добавляется строкой, а не
  веткой кода;
- сверка — без регистра и без знаков `_ - . : *`;
- первая строка — заголовок, если в ней есть знакомое имя. Флаг `header`
  решает вместо угадывания;
- правка руками: API заменяет угаданное целиком (экран присылает всё
  сопоставление), консоль `--map` дописывает к угаданному (человек правит одну
  колонку).

**Нормализация строки** (`sales/intake.py`):

| Поле | Правило | Непонятое |
|---|---|---|
| почта | без пробелов, нижний регистр; форма — общий `contacts.extract.EMAIL_RE`, ≤ 254 знаков | отказ строки: «нет адреса» или «не адрес почты» |
| домен компании | из колонки сайта, иначе из домена почты; бесплатная почта — общий `contacts.quality.FREE_MAILBOX_DOMAINS` | сайт не разобран при рабочей почте — домен из почты и замечание; бесплатная почта без сайта — отказ «нет сайта компании» |
| имя | «имя», иначе «first name» плюс «фамилия»; полное имя не повторяется | — |
| страна, язык | коды (`de`, `en`), нижним регистром | поле пусто, замечание |
| имя, должность, компания | по ширине колонки (255) | обрезано, замечание |

**Домен компании — корневой, как у доноров** (`domains.host` — ключ дедупликации,
по нему в 1.4 работают стоп-лист и дубли с другими направлениями):
`host_from_cell`, затем `donors.host.normalize_host`. Порядок неслучаен: общий
`normalize_host` бросает на ячейке с `[` (находка, передана). Зоны нет в списке
публичных суффиксов (`.test`, свежая зона) — хост целиком: без списка границу
компании не провести, а терять лида незачем.

**Отчёт** — `Problem(line, reason, cell, loaded)`: номер строки файла, причина
словами, ячейка как есть. `loaded=True` — лид загружен, не записано одно поле.
Сайт, страну и язык разрешено не знать, поэтому непонятые они стоят не дороже
пустых (урок L67 соседнего проекта).

**Предпросмотр базы не касается** — в нём нет сессии, и A7 «без записи» держится
построением. Колонки почты нет — лиды не считаются, флаг `needs_mapping`:
правда — «сопоставьте», а не «0 лидов» (A6).

**Загрузка** (`intake.load`):
- домены компаний заводит общий `DonorRepository.ensure_domains` пачками по
  тысяче, с `ON CONFLICT DO NOTHING` — список хостов уходит параметрами, а их у
  Postgres не больше 32 767 на запрос;
- лиды — одной массовой вставкой ORM, `source=import`, `status=new`,
  `contact_id` пуст (решение (а));
- журнал `sales_leads_imported` пишется здесь, а не в обвязке: загрузку зовут
  экран и консоль (урок L63). Автор — пользователь экрана; у консоли автора нет,
  `user_id` пуст. Детали: источник, «загружено», «отклонено»;
- ни одного годного лида — записи нет, журнала тоже: менять нечего.

**Google-таблица** (`sales/sheet.py`):
- ссылка разбирается здесь, запрос собирается из номера таблицы и листа —
  только `docs.google.com`, сама ссылка из поля не открывается;
- формы ссылки: `/edit#gid=`, `?gid=`, без схемы, «опубликовано в интернете»
  (`/d/e/…/pubhtml` → `pub?output=csv`);
- исходы — по замеру 02.10.2026 (запрос без входа) и уроку L10 соседнего
  проекта:

| Ответ Google | Исход |
|---|---|
| 200 `text/csv` (после 307 на googleusercontent) | таблица прочитана |
| 401, 403 или HTML при любом коде (L10: страница входа со статусом 200) | «таблица не открыта по ссылке — откройте доступ или загрузите CSV» — 400 |
| 404 | «таблица по ссылке не найдена — проверьте ссылку; если она верна, она закрыта» — 400 |
| 400 | «в таблице нет листа из ссылки (gid=…)» — 400 |
| сеть, 429, 5xx, иной код | «Google не ответил — повторите позже или загрузите CSV» — 502 |

- больше 10 МБ не читается — ни файл, ни таблица.

**API** (`backend/api/sales/`, роутер — в общем `api/app.py`):
- `POST /api/sales/import/preview` и `POST /api/sales/import` под
  `Permission.SALES`, формой `multipart/form-data`;
- поля: `file` или `link` — одно из двух; `mapping` — JSON «поле → колонка с
  нуля»; `header`; `delimiter`; у загрузки ещё `hypothesis_id`;
- форма, а не JSON с текстом: сервер получает байты, и отказ на cp1251 работает,
  а не превращается в кракозябры;
- состояния между шагами нет: мастер присылает источник оба раза, таблица по
  ссылке читается заново;
- право проверяется до чтения: без него сервер не ходит даже в Google;
- разбор — в пуле потоков (`asyncio.to_thread`), 5000 строк не держат цикл;
- отказы ядра — в общем `api/errors.py`, как у остальных разделов.

**Консоль** — `outreach sales-import --hypothesis <имя> (--file | --link)
[--map поле=колонка] [--header/--no-header] [--delimiter] [--dry-run]`:
- гипотеза — по имени с той же чисткой пробелов, что при заведении
  (`hypotheses.find`);
- отчёт печатается целиком и перед записью, и при `--dry-run`;
- коды выхода: 0 — готово, 2 — источник или сопоставление, 5 — нет гипотезы,
  8 — Google не ответил.

**Выключатель `SALES_ENABLED` загрузку не держит**: это работа с данными, а не
отправка. Первым его читает проверка ключей продаж (4.1).

## Stack / boundaries

`httpx`, `python-multipart`, SQLAlchemy, Alembic, argparse — всё уже в зависимостях,
новой нет. Продажи читают общее: `contacts.sweep_input`, `contacts.extract.EMAIL_RE`,
`contacts.quality.FREE_MAILBOX_DOMAINS`, `donors.host`, `DonorRepository.ensure_domains`,
`AccessRepository.record`. Направление «продажи → общее» контракт В1 (1.2) разрешает.
Общая почта продажи не импортирует.

## Rejected alternatives

- Свой читатель CSV в `sales/` — отклонено, потому что правило «один раз»: читатель
  таблиц из рук человека один на все направления.
- Правка общего `read_records` под байты — отклонено, потому что общий файл менялся
  бы ради одного вызывающего, а временный файл решает задачу без него.
- JSON с текстом файла вместо формы — отклонено, потому что браузер декодирует
  cp1251 как UTF-8 молча, и отказ общего читателя не сработал бы.
- Полный фильтр годности `contacts.quality.rejection_reason` для адреса лида —
  отклонено, потому что он для адресов со страниц, где `google.com` — служебный
  домен, а человек из компании на таком домене — законный лид. Годность адреса —
  очистка 1.4.
- Угадывание заголовка по содержимому (в первой строке нет «@», ниже есть) —
  отклонено, потому что первый лид без адреса молча стал бы заголовком.
  Незнакомый заголовок виден в отчёте строкой 1.
- google-api с сервисной учёткой и XLSX — отклонено планом фазы, потому что это
  новые зависимости.
- Сохранение источника между предпросмотром и загрузкой — отклонено, потому что
  это состояние на сервере, срок жизни и уборка. Мастер присылает источник
  второй раз.

## Risks

- Открытая по ссылке таблица видна всем, у кого есть ссылка. Это называется
  словами в отказе и в интерфейсе (1.5).
- Таблица по ссылке может измениться между предпросмотром и загрузкой: загрузка
  читает её заново, и итог называет, что легло на деле.
- Дубли внутри файла и против базы срез не режет — это 1.4. Повторная загрузка
  того же файла даёт повторных лидов, которых 1.4 отклонит как дубли.
- Список бесплатной почты общий и неполный (`bk.ru`, `web.de` и др.): такой
  адрес без сайта даст доменом компании почтовый сервис. Находка передана.

## Размер и разрез

Срез целиком — 18 файлов и 1730 строк при пределе 800 (без `delivery/`).
Владелец решил сливать его тремя PR, по порядку коммитов:
- **1.3a ядро** — синонимы, чтение файла, нормализация, отчёт, запись, журнал
  и миграция; тесты A1–A4, A6, A8 и миграции. 7 файлов, 801 строка — с записью
  номера ревизии в `.secrets.baseline`;
- **1.3b ссылка и консоль** — Google-таблица, байты с экрана, `outreach
  sales-import`; тесты A2, A5, A6, A9. 7 файлов, 571 строка;
- **1.3c API** — маршруты, регистрация, отказы в кодах; тесты A5–A8 через API.
  6 файлов, 367 строк.

Снимок сложности (`delivery/complexity-snapshot.json`) после перебазирования
каждой части пересобирается `scripts/complexity.py --update`.
