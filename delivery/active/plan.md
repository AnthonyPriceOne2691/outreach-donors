# Plan: срез 1.5, часть 1.5a — списки раздела на сервере

## Approach

- Списки — в `backend/api/sales/routes.py` рядом с предпросмотром и загрузкой 1.3c;
  чтение — `backend/features/sales/browse.py`: счётчики по гипотезам одним запросом с
  группировкой, лиды с фильтрами и сводкой по всем лидам, страница 20, предел 100.
- Перечень кодов причин отказа отдаёт сервер (`reasons`): экран строит фильтр из ответа и
  не держит свой список, который разошёлся бы с очисткой (1.4) на первой новой причине.
- Отказы — словами через общий `api/errors.py` (1.3c); право — `Permission.SALES`.

## Rejected alternatives

- Список лидов без серверных фильтров, с фильтрацией на экране — отклонено, потому что база
  гипотезы — тысячи строк, а экран получает по 20.
- Отдельный маршрут сводки — отклонено, потому что сводка по всем лидам идёт тем же запросом,
  что и страница, и экран делает один запрос на смену фильтра.
- Свой перечень причин на экране — отклонено, потому что коды пишет очистка, и перечень
  разошёлся бы с ней на первой новой причине.

## Risks

- Поиск подстрокой по адресу и имени на базе в десятки тысяч лидов — без индекса под
  подстроку; страница ограничена, запрос один. Замер на большой базе — заложено.

## Rollout / migration

Без миграции. Срез сливается двумя PR по решению владельца 04.10: эта часть — без вейвера
(4 файла, 688 строк), часть 1.5b — экран под вейвер строк владельца.

## Test / eval strategy

`tests/test_api_sales_screen.py` настоящим приложением на базе дерева: счётчики, порядок,
фильтры, страница, незнакомый код, 422, A4. Новые тесты на старом коде — красные
(verify-report).
