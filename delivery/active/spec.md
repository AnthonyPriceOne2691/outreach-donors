# Spec — срез 5.2 `sales-kommo`: клиент Kommo

## Problem

Интеграции с CRM в outreach-donors нет. Лид продаж («хочет пообщаться») должен уходить в Kommo
сделкой с контактом и компанией, а ссылка на сделку — человеку. Kommo — новый внешний провайдер;
запись в CRM, где работают люди, — внешний побочный эффект: из сервиса он не отзывается.

## In scope

- `KommoClient` (Protocol), `KommoFixture` (без сети, номера выдуманные и повторяемые, помнит
  созданное — для тестов 5.3), `KommoLive` (httpx), фабрика `build_kommo` по
  `SALES_KOMMO_PROVIDER` (`fixture` по умолчанию). `live` без поддомена, ключа, воронки, этапа
  или ответственного — `ConfigError` при сборке, до первого запроса.
- Методы: `find_contact(email)` — `GET /api/v4/contacts?query=`; `create_complex_lead(lead)` —
  `POST /api/v4/leads/complex`: «Email: <компания>», `pipeline_id`, `status_id`,
  `responsible_user_id`, теги «Email рассылка» и гипотеза; контакт — найденный по почте (номером)
  или новый (имя и рабочая почта); компания — название и сайт; `add_note(lead_id, text)`;
  ссылка `https://{subdomain}.kommo.com/leads/detail/{id}`.
- Транспорт: повторы на таймаут, обрыв, 429 и 5xx; пауза Kommo — из `Retry-After` или поля
  `retry_after` тела 429; не больше 7 запросов в секунду; 401 — отказ без повторов словами
  «ключ Kommo отклонён»; ответ без номера сделки — громкий отказ формы.
- Ключ — из настроек; в адресе, тексте ошибок и журнале его нет.
- Настройки `SALES_KOMMO_*` в `backend/config/sales.py` и `.env.example` (пустые, `fixture`);
  весь набор тестов — на `fixture` без ключа (`tests/conftest.py::_no_real_kommo`).

## Out of scope

- Передача лида (5.3): когда звать клиент, таблица передач, Telegram, запасной путь, тревоги.
- Обратная синхронизация статусов сделок из Kommo; поиск и слияние компаний; обязательные
  поля воронки сверх названных (станут видны на живом доступе — отказ 400 назовёт поле).
- Живая проверка на тестовой воронке — 5.5, после доступа и переподписи необратимого.

## Acceptance examples

| # | Вход | Ожидаемый выход | Тесты |
|---|---|---|---|
| A1 | контакт с этой почтой уже есть | сделка привязана к нему (`contacts: [{"id": …}]`), второго контакта нет; «похожий» адрес нечёткого поиска — не тот же человек | `test_a1_*` (5) |
| A2 | 429 с `Retry-After: 2` | пауза 2 с и повтор; успех — и на поиске, и на самой сделке | `test_a2_*` (2) |
| A3 | 401 | отказ `KommoAuthError` без повторов, словами «ключ Kommo отклонён …» | `test_a3_*` (3) |
| A4 | в ответе нет `id` сделки | `KommoFormatError` «Kommo ответил HTTP … без номера сделки … сделка могла создаться», без повтора | `test_a4_*` (9 форм) |
| A5 | `live` без ключа или поддомена | `ConfigError` при сборке, ни одного запроса | `test_a5_*` (3) |

Сверх примеров: запись не повторяется после отправки (`KommoUnconfirmedError`); пауза дольше
потолка — отказ с величиной, а не сон; незнакомая форма поиска — `KommoFormatError`, а не «никого»;
негодные поддомен, номера и ключ — `ConfigError` без значения ключа; частота — не больше 7 в
любую секунду.

## Сверено с документацией Kommo API v4

- `_embedded[contacts][0][id]` в `/leads/complex` привязывает существующий контакт; теги —
  `_embedded[tags]` с `name`.
- Успех `/leads/complex` — 200, список `{id, contact_id, company_id, request_id, merged}`.
- Пустой поиск контактов — 204 без тела.
- Предел — 7 запросов в секунду с IP; превышение — 429 с `retry_after` в теле (в примере 300);
  частые нарушения — блокировка доступа (403).
- Ошибки — `title`, `type`, `status`, `detail`, у 400 — `validation-errors` (`path`, `detail`).
- Примечание — `POST /leads/{id}/notes`, `note_type: common`, `params.text`; ответ —
  `_embedded.notes[].id`.
