# Spec: модуль «Продажи», срез 4.6a `sales-chain` — цепочка писем продаж в базе и экран правки

Часть 1 среза 4.6 (T1 из `F4-sending.md`): хранение шаблонов, правила записи, загрузка файлом, экран.
Сборка очереди, отправка, ключ с контактом и адрес получателя из лида — часть 2 (4.6b, общий код почты).

**Problem.** Шаблоны писем доноров — файлы в колесе, добивки берутся из файлов всегда. Репозиторий
публичный: тексты продаж там жить не могут. Нет ни места для первого письма и двух добивок продаж на
двух языках, ни правил, которые не пустят в шаблон поддельное «Re:», метрики Ahrefs, незнакомую
подстановку или вторую подпись, ни способа узнать, каким текстом написано письмо.

## In scope

- **`sales_chain_templates`** — шаблон шага: набор (гипотеза или общий — `hypothesis_id` пуст), шаг
  (1 — первое письмо, 2 и 3 — добивки), язык (`ru`, `en`), тема, тело, включён ли, кто и когда правил.
  Ключ — набор, шаг и язык (`NULLS NOT DISTINCT`: второго общего шаблона того же шага база не пустит);
  тема — только у первого письма (проверка базы); шаблоны не удаляются — выключаются.
- **Тело — в формате зон доноров** (`[имя] rewrite` / `[имя] fixed`, подстановка `{{имя}}`), хранится
  каноническим: зоны по порядку через пустую строку. Добивки — только `fixed` (модель в них не участвует,
  как у доноров); у первого письма переписываемая часть дотягивает до нижнего края коридора отличия.
- **Правила записи — одни для экрана, консоли и предпросмотра** (`chain_text.step_template` и `unsigned`):
  тема первого письма обязательна и без «Re:», «Fwd:», «Отв:»; у добивки темы нет; метрик Ahrefs нет
  (общий `guards.assert_no_metrics`); подстановки — только `{{name}}`, `{{company}}`, `{{site}}`;
  подписи и физического адреса нет ни зоной, ни подстановкой, ни текстом из настроек отправителя —
  их допишет сборка (4.6b) из «Отправителя» (3.1). Отказ — словами, первой причиной.
- **Набор гипотезы**: цепочка гипотезы на языке — своя целиком, если у гипотезы есть хоть один
  включённый свой шаг на этом языке, иначе общая целиком; шаги наборов не смешиваются (`chain.resolve`).
- **Версия цепочки** — `chain-` и 12 знаков sha256 от отсортированных «шаг, язык, тема, тело»
  включённых шагов цепочки (набор + язык); правка, вернувшая текст, возвращает и версию. Для 4.6b и
  калибровки: по версии узнают, каким текстом написано письмо.
- **Готовность для 4.6b** — `Chain.check_ready`: неполная цепочка — отказ словами «цепочка писем продаж
  (en, общий набор) не задана: нет первого письма, … — задайте на экране … или загрузите файлом».
  Умолчаний-текстов в коде нет.
- **API** под `Permission.SALES`: `GET /api/sales/chain[?hypothesis=N]` (шаблоны набора, включённые и
  нет, и цепочки по языкам: чья, полна ли, чего нет, версия; шаги, языки, подстановки и границы полей —
  от сервера), `POST /api/sales/chain` (записать шаг: завести или поправить), `POST /api/sales/chain/preview`
  (письмо глазами адресата: выдуманные значения, подпись и адрес из настроек, чего не хватает для
  отправки — без записи). Отказы — словами через `api/errors.py`.
- **Консоль** — `outreach sales-chain-load --file цепочка.json [--hypothesis "…"] [--update] [--dry-run]`:
  JSON вне копии репозитория (внутри — отказ до чтения), один файл — один набор, всё или ничего с
  номерами шаблонов, повтор не задваивает, отличия без `--update` не трогаются и называются.
- **Журнал** — `AuditAction.SALES_CHAIN_CHANGED` (значение — отдельной ревизией `ADD VALUE`): запись шага
  с экрана (прежние значения правленых полей, версия до и после), загрузка файла одной записью (счётчики
  и версии по языкам). Без изменений — без журнала.
- **Экран** — вкладка «Цепочка писем» в разделе «Продажи»: выбор набора, карточки языков (чья цепочка,
  полна ли, чего нет, версия), три шага с темой, началом текста, кто и когда правил; окно шага с
  «Показать письмо». Обе темы, 1440 и 390 — замеры.

## Out of scope

Сборка очереди продаж и отправка, ветки продаж в `recipients`/`template`/`sending`, ключ идемпотентности
с контактом, адрес получателя из лида, обязательный адрес по направлению (4.6b, T2–T3); письмо «вас
посоветовал коллега» для лидов `referral` (открытый вопрос — вариант первого письма в ключе шаблона);
удаление шаблонов; история текста (кроме журнала); наполнение настоящими текстами.
