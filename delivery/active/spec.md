# Spec: модуль «Продажи», срез 1.1b `sales-stage`, часть «а» — значение этапа и отказ продажам в письмах

Срез 1.1b идёт тремя PR (общий код почты — не модульный срез, предел 25 файлов и 800 строк):
**«а» — значение `sales`, отказ словами и путь писем (этот PR)**; «б» — ответы; «в» — API, отбор, экран.
Полная таблица инвентаризации — в черновике среза (`spec.md` уровнем выше); здесь — её часть «Почта: письма»,
сверенная с main `f9819da` (#196, #194, #180, #198, #197): после #175 — учётка платформы по направлению, после #191 —
отправка очереди пачкой, после #192 — пробный рекламодатель, после #197 — `sending.check_ready` одной строкой.

**Problem.** У общей почты два этапа, и почти каждая ветка устроена как «рекламодатели, иначе
доноры». Новый этап `sales` в такой ветке молча идёт путём доноров: очередь продаж собирается из
принятых доноров, письмо продаж уходит после проверки решения по донору, добивка теряется после
погашения срока (`KeyError` по словарю шаблонов — уже после фиксации срока).

## In scope

- `Stage.SALES` (`backend/features/core/domain.py`) и миграция `ALTER TYPE stage ADD VALUE IF NOT
  EXISTS 'sales'` отдельной ревизией `39e342cb2b21` после головы main `fc721be3d031`; значение в той
  же ревизии не используется.
- Громкий отказ — одно место с текстом «продажи к почте ещё не подключены»
  (`backend/features/core/stages.py`: `SalesNotConnectedError`, `permanent = True`; шлюз
  `mail_stage` → `MailStage`): API — 409 словами (`backend/api/errors.py`), консоль — словами и кодом
  выхода 9 (перечень консоли продаж `backend/cli/sales_commands.py`, `main.py` берёт его целиком), задача
  очереди — итог «не выполнена» с причиной.
- Разбор этапа целиком (`match` с `assert_never`, у `sending._check_review` — `donor_path` по узкому
  типу) в точках писем: следующий новый этап — ошибка mypy strict, а не путь доноров.
- Два обязательных пункта (решение владельца 05.10): добивка продаж не теряется молча — захват
  берёт только этапы с цепочкой, срок продаж цел, проход говорит вслух; очередь продаж не
  собирается из принятых доноров — у пути доноров больше нет параметра этапа.
- Отправка очереди пачкой (#191, просьбы соседней сессии): кнопка `POST /api/letters/send-queue` спрашивает
  мост подключения этапа (`core/stages.check_connected`) до счёта очереди и до задачи — продажам 409 словами;
  письмо продаж в пачке (`batch._send_one`) останавливает её словами отказа, а не общей «связью с почтой».
- Учётка направления — механизмом #175, без своей копии: ключ, ключ событий и список разрешённых
  этапа выбирает `config.outreach.mail_account(stage)`; со значением `sales` вебхук событий
  принимает события учётки продаж; письмо продаж отказывается до выбора её транспорта.

## Out of scope

Ответы (часть «б»), API-журнал, отбор прогона и экран (часть «в»). Настоящие ветки продаж в почте
(Ф4): шаблоны писем и добивок продаж, ящики продаж в балансировке, пробное письмо учёткой продаж.
