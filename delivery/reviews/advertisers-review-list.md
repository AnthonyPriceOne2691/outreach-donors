## Ревью рисковых мест

- безопасность: `bearer` — только в тестах API (`test_the_zone_reason_is_short_and_its_why_is_a_note`, `test_the_zone_reason_is_short_on_screen_and_whole_in_the_file`): запросы с пропуском тестовой учётки, как у соседних тестов. `auth` — контекст ханка `import { useSession } from '../auth/AuthProvider'` в `JudgePass.tsx` и `NicheQueue.tsx`, сам импорт не менялся. Права те же: «Пишем» и «Не пишем» стоят только при `can('prices')` у бизнесов ниши и `mayDecide` в очереди — `DecideButtons` прав не проверяет, его рисует тот, кто их проверил; «Переобойти спорные» — при `can('run')`. На сервере маршруты и права не тронуты: `reason_notes` и `advice` — новые поля прежних ответов на чтение (право `view`), ничего не пишут.
- транзакция БД: `commit` — только в тех же тестах: строка кандидата пишется `await session.commit()` до запроса к API. Код базы дифф не меняет: `shown_reasons` только читает причины строки, хранимый текст прежний (`nonprofit_reason` в `scoring._capped` даёт ту же фразу), выгрузка (`to_csv`) и консоль берут его целиком.
- производительность: `re.compile` в `backend/features/crawl/reason_words.py` — один шаблон `_NONPROFIT` при загрузке модуля; `shown_reasons` делает `fullmatch` по причинам одной строки (их единицы) и зовётся из `CandidateCard.of` и `AdvertiserCard.of` — на строку страницы (10 у очереди, 20 у списка). Выборки без границы и разбора в цикле по базе нет; риска нет.
- новый модуль: `reason_words.py` — чистые функции без состояния; `Reasons.tsx` и `DecideButtons.tsx` — компоненты без своих запросов; их тесты — `test_reason_words.py` и `Reasons.test.tsx`.
