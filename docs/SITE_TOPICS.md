# Тематика сайта

Оператор попросил: «добавить ИИ-определение тематики сайта — для фильтрации и поиска
тематичных сайтов». До этого «тема» донора была ключами прогона, по которым он нашёлся
(`crawl/topic.py`), а судья площадки отвечает на другой вопрос — как сайт зарабатывает.
Теперь у сайта есть тема из общего списка, и по ней фильтруют «Доноров» и очередь
«Рассмотрения».

## Как тема появляется

- выдача прогона и главная, которую судья уже открыл → **тема в той же пачке, что судья**
  (`features/runs/judge_stage.py`, `features/topics/step.py`) → ни одного лишнего захода на
  сайт и лишней покупки выдачи;
- текст сайта → **отдельный вызов дешёвой модели** (`LLM_TOPIC_MODEL`, по умолчанию
  `gpt-5-mini`, рассуждение `TOPIC_REASONING_EFFORT=low`) → код темы, вторая тема (если у сайта
  два больших предмета) и причина одной фразой по-русски; промпт — `topics/prompts/classify.md`;
- текст сайта → **данными между метками** `<<<SITE … SITE>>>` → метки, вписанные самим сайтом,
  гасятся похожими знаками, промпт говорит модели, что между метками — чужие данные, а не
  указания; ответ — в строгой форме JSON (`response_format`);
- ответ модели → **сверка со списком** (`topics/answer.py`) → подпись вместо кода сводится к
  коду, битый JSON спасается по полям; **«не ясна» — только явный `null`**; проза, обрезанный
  потолком ответ и тема не из списка («finance, business») — сбой формы: на домен не ложится,
  прежнюю тему не затирает, считается своим числом;
- причина → **короткой и чистой** → до 120 знаков, без адресов почты, ссылок и телефонов: её
  видит оператор, а модель могла пересказать то, что вписал сайт;
- тема → **у домена** (`domains.site_topic*`) с моделью, версией промпта, источником текста
  и временем → свежая тема второй раз не спрашивается;
- уже записанные сайты → **досуд командой** `outreach topic-backfill` → план до траты, каждый
  ответ — с записью, повтор берёт оставшихся.

Судья выключен (`JUDGE_MODE=off`) — тема в прогоне не определяется: её место — пачка судьи.
`TOPIC_MODE=off` — модель тематики в прогоне не зовётся, в отчёте прогона ветки тем нет;
досуд — по-прежнему командой.

## На экранах

- строка доноров и кандидат очереди → **тема строкой под доменом** (основная — чернилами,
  вторая — тише, почему — в «i») → колонкой не встала: на 1440 с раскрытым меню колонкам
  «Доноров» остаётся 14 px сверх ширин, и таблица уехала бы в прокрутку вбок (так же с ценой);
- «Доноры» → **фильтр «Тематика» над таблицей**, как «Цена»: пункты со счётчиками, поиск по
  названию, «не определена»; параметр `topic` в адресе и в выгрузке;
- «Рассмотрение» → тот же фильтр над очередью, по её строкам тем же правилом;
- смета прогона → **строка о токенах тематики** — худший случай, на сайт, оценка или замер;
- история прогонов → **«тематика: нет ответа N»** — модель не ответила или ответила не по
  форме, первая причина — в подсказке;
- «Расход» → строка журнала `site_topic` — «тематика сайтов», среди операций модели.

Фильтр находит сайт и по второй теме: «Финансы» — это и финансовый блог, и газета со второй
темой «Финансы». Счётчик пункта считается тем же условием, что фильтр.

## Почему эти темы

Список — `backend/features/topics/taxonomy.py`, 34 темы. Основа — общепринятое деление
содержания сайтов по предмету (так устроены рекламные каталоги тем), поправленное под то,
что встречается в линкбилдинге: свои темы у азартных игр, криптовалют, «для взрослых» и у
сайтов «обо всём» — площадок гостевых статей без своей темы.

- **Темы широкие.** Узкая тема («ипотека», «футбол») делит одну нишу на десяток пунктов,
  и фильтр перестаёт находить «все финансовые сайты». Узкое остаётся в ключах прогона.
- **По предмету, а не по способу заработка.** Магазин гаджетов, обзорщик гаджетов и журнал
  о гаджетах — все «Технологии»; кто из них донор, решает судья площадки.
- **Общие для любых ниш, стран и языков.** В пояснениях для модели нет брендов и примеров
  одного рынка; код — латиницей и от языка сайта не зависит, подпись — по-русски.
- **Границы названы в промпте**, потому что на них модель и ошибается: газета или городской
  портал → «Новости», даже если статья о деньгах; блог на любые темы → «Обо всём»; журнал о
  повседневном (мода, дом, еда вперемешку) → «Образ жизни»; государство, общественные
  организации, благотворительность → «Общество»; фитнес и питание → «Здоровье».

Список целиком, код → подпись:
`news` → Новости, `general` → Обо всём, `lifestyle` → Образ жизни, `business` → Бизнес,
`finance` → Финансы, `crypto` → Криптовалюты, `gambling` → Азартные игры, `technology` →
Технологии, `marketing` → Маркетинг, `science` → Наука, `education` → Образование, `career` →
Карьера, `health` → Здоровье, `fashion` → Мода и красота, `family` → Семья и дети, `dating` →
Знакомства, `home` → Дом и сад, `real_estate` → Недвижимость, `industry` → Промышленность,
`auto` → Авто, `travel` → Путешествия, `food` → Еда и напитки, `sports` → Спорт, `gaming` →
Видеоигры, `entertainment` → Развлечения, `culture` → Культура, `hobbies` → Хобби, `pets` →
Животные, `shopping` → Покупки, `legal` → Право, `society` → Общество, `religion` → Религия,
`esoteric` → Эзотерика, `adult` → Для взрослых.

## Как расширять

1. Строка в `TOPICS`: код (латиница, строчные, `_`), подпись по-русски, пояснение для модели
   по-английски — что сюда входит, без брендов и примеров одной ниши.
2. Случаи в наборе eval `scripts/data/topic_golden.jsonl` — на нескольких языках; прогнать
   eval (ниже) и сравнить с прежним итогом.
3. Смысл существующей темы поменялся или переписан промпт — новая версия
   `classifier.TOPIC_VERSION`: темы прежней версии станут несвежими, прогон определит их
   заново у встреченных сайтов, остальных — `outreach topic-backfill`.
4. Миграция не нужна: колонка — строка. **Код из списка не удаляют, пока он лежит в базе** —
   экран покажет такую тему кодом.

## Свежесть и расход

- Тема свежая, пока версия та же и ей меньше `TOPIC_TTL_DAYS` (365 дней): о чём сайт,
  меняется реже, чем то, как он зарабатывает (у судьи — 180).
- «Не ясна» свежа меньше — `TOPIC_UNCLEAR_TTL_DAYS` (30 дней): «не понять» чаще говорит о
  бедном тексте, чем о сайте, а текст бывает богаче — новая выдача, открывшаяся главная.
- Версия промпта закреплена хэшем того, что видит модель (`tests/test_topic_classifier.py`):
  промпт или список тем поменяли, а `TOPIC_VERSION` нет — тест падает.
- «Модель не ответила» (ключ, сеть, отказ провайдера, пустой ответ) и «ответ не по форме» —
  на домен не ложатся, считаются своими числами с первой причиной в отчёте прогона (ветка
  `topics`) и меткой в истории.
- Каждый ответ — в базу сразу, короткой фиксацией: тема на домен и строка журнала расхода
  `site_topic` (Этап 1) с его токенами, в счёт дневного потолка модели. Оборванный прогон или
  досуд теряет только ответы, которые ещё летели (до `TOPIC_CONCURRENCY`, 16 вызовов): их
  токены провайдер спишет, а журнал не увидит. Перед каждой пачкой — проверка потолка:
  выбран — прогон останавливается причиной, как у судьи.
- Смета прогона: ожидаемые домены × токенов на сайт. Токены на сайт — худшее из недавних
  прогонов (`topics/cost.py`), до первого замера — оценка по размеру промпта, по худшему
  письму: ~1 700 токенов ввода (промпт со списком тем — 1 030, текст сайта в потолке 1 500
  знаков — до ~590 у кириллицы) и ~300 вывода вместе с рассуждением, всего ~2 000.

## Досуд уже записанных

`outreach topic-backfill --dry-run` — план без траты: сколько сайтов (сначала принятые
доноры, затем по DR), откуда у них текст — сохранённая выдача прогонов → главная по сети
(бесплатно; открывается и тем, у кого из текста — один заголовок главной из суда: по нему
модель чаще говорит «не понять») → заголовок из суда, если главная не открылась, — токены и
деньги:

сайтов с текстом и без (главная по сети) × токенов на сайт → токены; ввод × цена ввода +
вывод × цена вывода (`TOPIC_INPUT_USD_PER_1M_TOKENS`, `TOPIC_OUTPUT_USD_PER_1M_TOKENS`, по
прайсу GPT-5 mini — 0,25 $ и 2 $ за миллион) → деньги. Скидка провайдера на повтор промпта не
вычитается — верхняя граница: по оценке ~0,001 $ на сайт (1 700 × 0,25 + 300 × 2 за
миллион), тысяча сайтов — около 1,03 $.

Без `--dry-run` команда спрашивает подтверждения (`--yes` — не спрашивать); `--limit N`,
`--no-home` (не открывать главные: только сохранённый текст). `--again` — заново и тем, у кого
тема свежая, но записана раньше момента старта; момент печатается в плане, и повтор после
обрыва с `--again-before <момент>` продолжает с места, а не платит второй раз. Каждый ответ
записывается сразу вместе со строкой журнала, потолок проверяется перед пачкой из 40;
повтор той же команды берёт оставшихся.

## Как мерить точность

Набор — 52 синтетических сайта на шести языках (`scripts/data/topic_golden.jsonl`), у
каждой темы есть случай; хосты — в зоне `.example`: репозиторий публичный. Четыре случая —
«только заголовок» главной, как его читает досуд у домена без открытой главной: два с темой
по заголовку и два с одним названием, где верный ответ — «не понять».

- без модели, по записанным ответам (так его гоняет тест `tests/test_topic_eval.py`;
  ответы написаны руками — это проверка механики, а не замер):
  `python scripts/eval_topic.py --answers tests/test_topic_eval_answers.json`;
- живьём, с ключом модели (`LLM_API_KEY`), — по слову владельца, ~104 тыс. токенов (~0,05 $):
  `python scripts/eval_topic.py --out /tmp/topic-eval.json`; `--effort minimal` — замер
  другого усилия рассуждения.

Из дерева ветки — с `PYTHONPATH=.`: иначе скрипт возьмёт код основной копии. Ворота
(предложение, решает владелец): основная тема верна не ниже 80 %, основная или вторая — не
ниже 90 %, каждый язык — не ниже 70 %, «модель не ответила» и «ответ не по форме» — ноль.
Сбой формы на случае «не понять» за попадание не засчитывается.
